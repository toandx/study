Claude Domain 1.
1. Different Agent vs Workflow?
- Worklow: A developer-authored sequence where control flow is fixed at design time. Your code decides the order, and the model just fills in each step
- Agent: A system where the model decides the next action at runtime, driving a loop of reason, act, and observe until it hits a stopping condition.
2. What is Augmented LLM? Augmented LLM has features:
- Retrieval: Pulling relevant context into the prompt so the model answers from real information instead of guessing.
- Tool: Let the model take action in the world, like query DB or call a service
- Memory: Carrying state across a task so the model can build on what it has already done. Keep context. 
3. Agentic system:
- At one end, your code owns the order of operation
- At the other, the model owns it at runtime
- Fixed paths, are predictable and easy to test
- Model-driven paths: Adapt to inputs you didn't foresee
5. Three signal you need an agent: 
- Open ended space: The task can unfold (phát triển) in many directions you simply can't list.
- Unknown steps: You can't predict how many actions the job will really take to finish.
- Model chooses tools: Let the model itself pick which tool and when. 
6. Is a workflow enough?
- Can you write the steps out in a fixed order? Does the same input alway take same path? If yes, workflow is enough
- Prove workflow can't do before pay for agent
7. 3 workflow shape:
- Prompt chaining: P1 -> P2 -> P3 Break a task into a fixed sequence when each call works on the previous output
- Routing: User -> ? -> P1 or P2 or P3. Classify an incoming request and send it to the handler built for that case
- Parallelization: User -> All P1,P2, P3 run in parallel. Run independent pieces at once, or run the same task several times and compare.
4. Best practice to choose Workflow or Agent?: 
- Prefer the simplest design that solve the task
- Three signals to use Agent: Open space, unknown step, model-chosen tools
- Workflow shapes: Prompt chaining, routing, parallelization
- Hybrids workflow and agent: Wrap an agent inside a workflow stage
5. Disadvantage of build Agent, not build Workflow:
- Latency: A loop makes serveral call in sequence, so users wait longer than for 1 response
- Token cost: Every turn re-sends the growing context, so bill grow with each step.
6. Advantage of Agent:
- Task performance: The model's ability to adapt to adapt to messy output. A rigid script of Workflow cann't bring.
Trade off between Latency + Token cost to get Task performance
7. Compare advantage Workflow vs Agent:
- Workflow: Predictable, cheaper, and faster. It does the same thing on every run, which makes it easy to test and easy to trust. Suitable when task is well defined.
- Agent: Flexible and adaptive, bust it cost more, run slower, and can have mistake that a workflow script would never make.
8. Why a loop of Agent cost more?
- More turn: The loop keeps calling the model until task is done, as each call bill.
- Every accumulate: instruction, tool calls, and results.
- Bigger context: Every turn carries the full history, so later turns are the priciest ones.
- Compounding error: A wrong step early feeds every step after it, and the model build on the mistake. Step A fail -> Step B fail -> ...
- Slower responses: Sequential round trips add latency.
9. What is compounding error?
- Compounding error (lỗi tích lũy) are sneaky cost (chi phí ẩn) of a loop
- In workflow, if step have mistake, your code can catch it. But in agent, a mistake step become input for next decision. By a few turn later, it can be far of track (đi lệch hướng) with no point of failure (dấu hiệu lỗi). The more step without a checkpoint, the more room to make big failure.
10. Why workflow stay reliable?
- Predictability: A fixed path produce the same behavior every run, so you can reason about it
- Auditability: You can trace exactly which step ran, in which order and why?
- Consistency: No runtime improvisation, so the behavior doesn't drift (change) from one call to the next.
11. What is Hybrid design Agent vs Workflow? How many type?
- Agent inside a stage of Workflow: Drop a scoped agent into just 1 open-ended step of an otherwise fixed pipeline, where flexibility is needed
- Workflow around Agent: Agent in center, make decision. The workflow handle ordering, validation, and error handling, support execute this decision, so you get predictability at the edge and adaptability only in the core.
12. What is 3 core role in Agent?
When you push 1 agent to handle big, messy job end-to-end, it context ballons (Phình to) and answer get worse (tồi tệ). A managet delegate piece to subagent can fix that problem. Need use subagent:
- Manager: Orchestrator agent. Decompose goal, delegate subtask to subagent, synthesize
- Subagent
- Delegation
13. Why need use Sub-agent:
- Context isolation
- Parallelization: Independent subagent run concurrently
- Tool restriction: Each subagent get only tools its assigned task need.
14. 3 guardrail on scope Subagent?
- Least privilege: Give subagent only tool and permission its task requires
- Side effect boundary: A scoped sub-agent should produce no write or action beyond its assigned subtask
- Result validation: Manager check each return result before trusting it in final answer.
15. Common anti-pattern when use Sub-Agent?
- Overly board scope, give sub-agent too much job, it burn token, and response something muddy. Keep each sub-agent narrow.
- Unpowered context. Give it too little context, data
- Parallel only thinking. Treat sub-agent only like parallel worker. Speed is nice, but context isolation,keep manager windows clean mới là thế mạnh của Sub-agent. Orchestrator-worker decide subtasks at runtime, unlike fixed parallelism.
16. Why subagent run in isolation?
- Own context windows: Each subagent run in context windows fully separate from manager
- No inherited history: Subagent does not receive manager conversation, tool result, or system prompt.
- Final message return: Only sub-agent's final msg goes back to manager, to its intermediate steps.
- Subagent only see own prompt, CLAUDE.md, and tool, receive anything you expilcitly pass to task. Never manager history, manager result, many system prompt.
- Isolation bound token growth: Only summary result of SubAgent are retainer in manager context.
17. 3 Authority Boundaries of Sub-Agent:
- Least privilege
- Side-effect limit: No write, action outside of subtask
- Contained blast radius: Is subagent misbehaves, it limited scope and tool, keep damage small. 
18. Setup Claude SDK?
- Agent SDK
- query(): Run standalone agent loop, each call start a fresh session by default.
- No need Command Line tool. 
19. Config to run Claude Query:
- System_prompt: Set agent's role and instruction
- List tool allow agent to use
- Select model

20. Stream to read message:
- Init message open the run
- Assistant and tool message show reasoning and result in order
- A final result message close the run with cost and status
21. 3 trait (đặc điểm) of Claude Run :
- Standalone
- Streamed: Message arrive as an sync iterator, read live as the agent work, not in 1 block (gửi response từng phần ngay khi done)
- Session-scope: Fresh session each call.
22. How agent loop run?
Claude receive prompt, tool, history and init message
=> Claude response with text or tool call
=> Agent SDK executes tool and feedback result
=> Claude read result, reason and turn repeat if it call more tool
- Repeat until goal is met, Claude call no tool.
- Turn is 1 round trip: Claude request tool, SDK run, feedback. Turn end when tool return result. 
23. 5 type of message?
- System Message open the run, include init subtype.
- Assistant Message carries Claude's text and tool calls
- User Message deliver tool result back into the loop
- StreamEvent appears only when partial streaming in on. 
- Result Message close the run with cost and status. include subtype (status), total_cost_id, num_turns and session_id (for audit and resume). Only success subtype carries result text, error subtype return nothing.
24. How to set bound for Agent Loop?
- Set max_turns for loop. Hitting it stop the loop and return error result
- Set max_budget_usd, max spend in dollars. Check between call, so a run can overshot before it halts with budget error.
- Default no cap (no bound). Developer must set bound if needed.
25. What happend when Agent hit limit?
- Code see error result, execution stop
- Wrap it in try exception if you want to keep going
- A streaming session stays alive instead of raising
- Reading a stopped run: stop_reason, num_turns, session_id
